# hash

A small, self-hosted URL shortener. It stores each destination and creates a short link that redirects to it. Existing compressed fragment links from the original page still resolve.

## Run

Requires Node.js 20 or newer.

```sh
npx @theshantanujoshi/hash serve --port 3000
```

In another terminal, create a link:

```sh
npx @theshantanujoshi/hash create https://example.com/a/long/address
```

The command prints the new short link. Links are saved to `hash-links.json` in the server's current directory. Keep that file and its backups: losing it breaks every generated link. Run only one server process per data file.

For a public deployment, set the address people will visit and bind to the network interface:

```sh
hash-links serve --host 0.0.0.0 --port 3000 --base-url https://links.example.com --data /path/to/hash-links.json
hash-links create https://example.com/page --server https://links.example.com
```

Put HTTPS and access controls or rate limiting for `POST /api/links` at the reverse proxy. The server accepts link creation without sign-in, so do not expose that endpoint to untrusted users without protection.

## API

`POST /api/links` with JSON `{ "url": "https://example.com/page" }` returns status 201 and `{ "id", "url", "shortUrl" }`. `GET /:id` redirects with status 302. Only HTTP and HTTPS destinations are accepted. The package also exports `createShortener({ dataFile, baseUrl })`, which returns a Node HTTP server you can listen on yourself.

## Development

```sh
npm install
npm test
npm pack --dry-run
```

Version `0.1.0` introduces the stored-link service. URLs generated by the previous static page had compressed `#` fragments; the GitHub Pages entry point and the server web page still decode them. Those old links depend on the original Pages address staying online.
